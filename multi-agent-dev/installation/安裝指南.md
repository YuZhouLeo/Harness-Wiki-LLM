# 多代理工作流 Skill 安裝指南（3 步驟）

> 本指南針對「人類在新機器上把這套工作流從零裝好」。AI 想跑步驟去看 [README.md](README.md) §「資料夾結構」與本檔的 Step 1-3。

---

## 需要先有的東西

- 已安裝 Claude Code（CLI 或 IDE 擴充）
- 已有 ChatGPT 訂閱或 OpenAI API key（驗證者 Codex 用）

> 各專案不需要是 Next.js / TypeScript——工作流本身與技術棧無關。也不需要是 git repo（無 git 時 lesson-keeper 降級為純 Read，仍可運作）。

---

## Step 1：把 multi-agent-dev skill 安裝到 `~/.claude/`

把本資料夾的母目錄（`multi-agent-dev/`）整包擺到 `~/.claude/skills/`，並把 3 個 subagent 擺到 `~/.claude/agents/`：

Bash（Git Bash / WSL / macOS / Linux）：
```bash
# 假設你拿到的安裝包在 /tmp/multi-agent-dev-install/
mkdir -p ~/.claude/skills ~/.claude/agents

# skill 主目錄（含 SKILL.md / codex-prompts / spec / templates / adr / installation）
cp -r /tmp/multi-agent-dev-install/multi-agent-dev ~/.claude/skills/

# 3 個 user-level subagent
cp /tmp/multi-agent-dev-install/agents/planner.md       ~/.claude/agents/
cp /tmp/multi-agent-dev-install/agents/executor.md      ~/.claude/agents/
cp /tmp/multi-agent-dev-install/agents/lesson-keeper.md ~/.claude/agents/
```

PowerShell：
```powershell
New-Item -ItemType Directory -Force "$HOME/.claude/skills","$HOME/.claude/agents"

Copy-Item -Recurse "C:/path/to/install/multi-agent-dev" "$HOME/.claude/skills/"
Copy-Item "C:/path/to/install/agents/planner.md"       "$HOME/.claude/agents/"
Copy-Item "C:/path/to/install/agents/executor.md"      "$HOME/.claude/agents/"
Copy-Item "C:/path/to/install/agents/lesson-keeper.md" "$HOME/.claude/agents/"
```

驗證：
```bash
ls ~/.claude/skills/multi-agent-dev/SKILL.md   # 應存在
ls ~/.claude/agents/                            # 應列出 planner / executor / lesson-keeper
```

## Step 2：merge SendMessage 實驗 flag 到 `~/.claude/settings.json`

**這一步沒做，整個工作流會在第一次 SendMessage 時失敗、整個 run 報廢**。

打開 `~/.claude/settings.json`，把 [整合片段/settings.json.片段](整合片段/settings.json.片段) 的 `env` 區塊 merge 到**頂層**（不可放進 `permissions` 內，否則不會生效）：

```json
{
  "permissions": { "allow": [...既有內容...] },
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```

> 建議先備份：`cp ~/.claude/settings.json ~/.claude/backups/settings.json.bak`

存檔後在 Claude Code 主對話輸入：

```
ToolSearch query="select:SendMessage" max_results=1
```

回傳 SendMessage 完整 schema 即啟用成功。回 `No matching deferred tools found` 表示尚未生效——重檢 settings.json 結構。

> 好消息：settings.json 的 `env` 變更**會熱載入**，不需要重啟 Claude Code。

詳細排錯：[spec/SendMessage子代理續用使用指南.md](../spec/SendMessage子代理續用使用指南.md) §1, §5.2。

## Step 3：給每個專案（首次跑工作流前）填上 invariants + `.gitignore`

工作流本身全域已就位，但**每個專案首次跑前**建議補兩件事：

### 3.1 invariants.md（可選但強烈建議）

把 [invariants.md.範本](invariants.md.範本) 複製到 `<project>/docs/invariants.md`，依範本說明列出本專案的硬規則：

```bash
cd <project>
mkdir -p docs
cp ~/.claude/skills/multi-agent-dev/installation/invariants.md.範本 docs/invariants.md
# 按範本說明填內容
```

> 不填也能跑：impl-validator prompt 內已有 fallback 邏輯——若 `docs/invariants.md` 不存在則改以 `AGENTS.md` / 專案規範為準。

### 3.2 `.gitignore` 規則（避免 run log commit 進 repo）

把 [整合片段/.gitignore.片段](整合片段/.gitignore.片段) 的內容追加到 `<project>/.gitignore`：

```
# 多代理工作流：單一 run 的完整時間線不 commit（INDEX.md 例外保留）
wiki/runs/[0-9]*.md
```

> `wiki/runs/INDEX.md` 與 `wiki/lessons.md` 仍 commit；只有時間戳開頭的單一 run log 不 commit。

### 3.3（可選）給 AGENTS.md 補一行指標

如果新專案使用 AGENTS.md，可加一行指向 skill：

```markdown
## Multi-agent workflow

多代理工作流：使用全域 `multi-agent-dev` skill。觸發語：「啟動多代理開發」或 `/multi-agent-dev`。
細節見 `~/.claude/skills/multi-agent-dev/SKILL.md`。
```

完整片段見 [整合片段/AGENTS.md.片段](整合片段/AGENTS.md.片段)。

## Step 4（自動，無需動作）：Codex plugin

驗證者由 Codex 透過 [codex-plugin-cc](https://github.com/openai/codex-plugin-cc) 擔任。如尚未安裝：

```
/plugin marketplace add openai/codex-plugin-cc
/plugin install codex@openai-codex
/reload-plugins
/codex:setup
```

`/codex:setup` 互動精靈會問是否啟用「自動 stop hook」——**選擇關閉**。理由：自動 stop hook 會讓每次 Claude 回應結束都被自動 review，干擾調度節奏（[adr/0002](../adr/0002-codex-as-validator-agent.md) §決策第 5 點）。

驗證可用：
```
/codex:status
```

## Step 5：端到端煙霧測試

在任一 repo 跑：

```
啟動多代理開發：在 README.md 結尾加一段 dummy 文字
```

預期觀察（按出現順序）：

- 主代理載入 `multi-agent-dev` skill（系統有 `<command-name>` 標記）
- 主代理 Write `wiki/runs/<時間戳>-readme-dummy.md` 開 run log（若 `wiki/runs/` 不存在會先建立）
- planner spawn → 寫一份簡短計劃書到 `plans/<功能>計劃.md`
- plan-advisor 大概率 0 建議直接通過
- executor spawn → 改 README.md → lint/test PASS
- impl-validator PASS（單行字加句不會踩任何 invariant）
- lesson-keeper spawn → 回「本輪 0 條可萃取」（dummy 任務無原則可萃取，是合法結果；若 `wiki/lessons.md` 不存在，會自動 Write 骨架）
- INDEX.md 追加一行 `✅ PASS（plan=1 / impl=1 / lessons=0）`

跑完後檢查：

- [ ] `wiki/runs/INDEX.md` 有新增一行
- [ ] `wiki/runs/<時間戳>-*.md` 存在且時間線完整
- [ ] `plans/` 有計劃書
- [ ] README.md 有 dummy 文字

## 失敗模式速查

| 現象 | 通常原因 / 看哪份檔 |
|---|---|
| Skill 沒被觸發 | description 不夠強烈；直接打 `/multi-agent-dev` 顯式叫起 |
| 第一次 SendMessage 失敗 | SendMessage flag 沒啟用，回 Step 2 |
| Codex 指令找不到 | Codex plugin 沒裝好或沒 reload，回 Step 4 |
| 主代理破戒（自己跑 Bash / 讀 code） | 回讀 `~/.claude/skills/multi-agent-dev/SKILL.md` §違規檢查清單 |
| 計劃顧問跟規劃代理一直不同意 | `~/.claude/skills/multi-agent-dev/spec/多代理協作工作流計劃.md` §3.2.1 advisor-stuck |
| 實作驗證一直 FAIL | spec §3.2.2 handoff |
| Codex 兩個 session 弄混 | `~/.claude/skills/multi-agent-dev/adr/0003-split-plan-advisor-and-impl-validator.md` §硬規則 |
| lesson-keeper 寫了廢話條目 | `~/.claude/skills/multi-agent-dev/adr/0004-lessons-three-writing-principles.md` §三大原則 + §自我檢查清單 |
| Run Log 應該長什麼樣 | `~/.claude/skills/multi-agent-dev/adr/0005-run-log-md-timeline-format.md` |
| 為什麼上限 = 3 輪而不是 5 | `~/.claude/skills/multi-agent-dev/adr/0006-max-retry-three-rounds.md` |
