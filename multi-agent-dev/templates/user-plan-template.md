# 使用者計劃書範本

> 本檔是**使用者啟動多代理流程前自己寫的計劃書範本**——不是 planner 產出物，也不是 Codex 看的檔。
> 路徑：`plans/<功能名>計劃.md`（**cwd 相對**），命名與存放慣例見全域 `CLAUDE.md` §計劃書 / 規劃文件流程。
>
> planner 在步驟 1 會讀這份檔 → 輸出工作拆分到 `plans/<功能名>-工作拆分.md`，不會回頭改這份檔。
>
> 範本是**建議性**的，不是強制 schema。planner 遇到缺欄位的計劃書要寬鬆處理（自己補預設假設並在工作拆分檔註記）；缺到完全無法推斷工作邊界才回 advisor-stuck 等使用者補。

---

## 1. 功能目標（必填）

<一段話描述：要做什麼、為什麼、要解決誰的什麼痛點>

例：
> 在 portfolio 頁面新增「歷史交易頁計」分頁，讓使用者看到每年/每月的已實現損益總計與單月明細，解決目前只能看當前持倉、看不到歷史獲利狀況的問題。

## 2. Acceptance Criteria（必填）

> 用「驗收條件」格式，每條一行，可單獨打勾。planner 會用這些條目決定工作項拆分與測試策略。

- [ ] <可驗證條件 1>
- [ ] <可驗證條件 2>
- [ ] <可驗證條件 N>

例：
- [ ] 使用者能切到「歷史交易」分頁，預設顯示當前年度
- [ ] 表格欄位含：交易日、商品、買賣方向、數量、單價、已實現損益
- [ ] 可下拉切換年度（最早到 2020）
- [ ] 月份分組摺疊；點該月可展開該月所有單筆交易

## 3. 影響檔案範圍（建議）

> 若你已知大概要動哪幾個檔，列在這。planner 會以此為起點再擴充；若你完全沒指定，planner 會自己 grep 推斷。

- 新增：`app/(root)/portfolio/history/page.tsx`
- 改動：`components/portfolio/PositionTable.tsx`
- 改動：`lib/portfolio/aggregate.ts`

## 4. 測試策略（建議）

> 若有偏好（單元 / 整合 / E2E、必測項目），寫在這。planner 會在工作拆分時對應到具體測試任務。

- 已實現損益計算邏輯 → unit test (jest)
- 年度切換 → 整合測試

## 5. 風險與回滾（建議）

> 已知風險、回滾條件、相依性。planner 會在工作拆分時把高風險項排到前面，並提醒測試覆蓋。

- 高風險：已實現損益計算與後端對帳不一致 → 回滾條件：抽樣 5 筆對 broker 報表，誤差 ≥ 1 元就回滾
- 相依：需要 PSC 拉歷史對帳單，憑證需事先匯入

## 6. 不要寫的內容（這由 planner 負責）

> 以下內容**不要**在這份計劃書寫，會被 planner 覆蓋或忽略：

- ❌ 工作項拆分（Task A / Task B …）—— planner 步驟 1 產出
- ❌ 實作順序與相依圖 —— planner 步驟 1 產出
- ❌ 可並行 vs 必須順序的標註 —— planner 步驟 1 產出
- ❌ 具體 code snippet —— executor 步驟 6 產出
- ❌ ADR 條目 —— 若新增依賴或破壞既有 ADR，由 planner 在工作拆分檔提醒

## 範本使用注意

- 必填段（§1、§2）缺一個 → planner 會回 advisor-stuck 要使用者補。
- §3–§5 缺 → planner 自己推斷並在工作拆分檔的「假設」段落明列。
- §6 是教學性質，正式計劃書可刪除這段以保持精簡。
